# راه‌اندازی انتقال رسانهٔ آوید

اصلاح کد به‌تنهایی جای سرور TURN را نمی‌گیرد. وب و سرویس Socket.IO صرفاً
سیگنالینگ/چت را منتقل می‌کنند. مدرس و دانشجو باید یک مسیر مستقیم یا TURN
قابل‌دسترسی داشته باشند. پورت‌های ۳۹۰۰ و ۳۰۰۵ مسیر رلهٔ رسانه نیستند.

## گزینهٔ ۱: TURN موجود یا سرویس مدیریت‌شده

در `.env` فعلی آوید تنظیم کنید (نمونه‌ها واقعی نیستند):

```dotenv
STREAM_TURN_URLS=turn:turn.example.org:3478?transport=udp,turn:turn.example.org:3478?transport=tcp,turns:turn.example.org:5349?transport=tcp
STREAM_TURN_SECRET=SHARED_SECRET_MATCHING_COTURN_AT_LEAST_32_CHARACTERS
STREAM_TURN_TTL_SECONDS=3600
STREAM_ICE_TRANSPORT_POLICY=all
```

سرور باید از Coturn TURN REST با `use-auth-secret` و `static-auth-secret`
پشتیبانی کند. رمز حساب ثابت یک سرویس تجاری با shared secret یکسان نیست.
کلید اصلی فقط در سرور وب و تنظیمات Coturn می‌ماند؛ مرورگر عضو مجاز کلاس
نام کاربری و اعتبارنامهٔ موقت دریافت می‌کند. این پاسخ `private, no-store` است.
کلیدها را در `NEXT_PUBLIC_*`، گیت یا پیام‌های پشتیبانی قرار ندهید.
کلاینت برای کلاس‌های طولانی قبل از انقضای اعتبارنامه تنظیمات را تازه و رسانه
را دوباره مذاکره می‌کند؛ چت/عضویت از نو ساخته نمی‌شود.

## گزینهٔ ۲: Coturn روی همین VPS لینوکس (Docker)

این گزینه جدا از Compose اصلی است و پورت‌های وب، دیتابیس و سایر پروژه‌ها
را تغییر نمی‌دهد. اسکریپت، IP عمومی مستقیم روی کارت شبکه و آزادبودن
پورت‌ها را بررسی می‌کند؛ اگر تداخل باشد متوقف می‌شود. برای VPS پشت NAT،
پورت‌های متفاوت یا چند TURN، تنظیم دستی لازم است.

```bash
cd /opt/avid
bash deploy/turn/setup.sh 5.159.49.132
```

IP را فقط اگر هنوز IP عمومی همین سرور است استفاده کنید. اسکریپت رمز تصادفی
می‌سازد، کانفیگ خصوصی و متغیرهای TURN را می‌نویسد و از `.env` قبلی در `/root`
بکاپ می‌گیرد. دیتابیس، آپلودها و سایر متغیرهای `.env` حفظ می‌شوند.
سرور TURN را به‌صورت خودکار روشن نمی‌کند و فایروال را تغییر نمی‌دهد.

در فایروال میزبان و پنل ارائه‌دهنده، **3478 UDP/TCP** و
**49160–49200 UDP** را برای این سرور باز کنید. سپس:

```bash
docker compose -f deploy/turn/compose.yaml up -d
bash deploy/update.sh
```

کانفیگ، احراز هویت، اعتبارنامهٔ زمان‌دار، محدودیت تخصیص و منع دسترسی رله
به آدرس‌های خصوصی/loopback دارد. پورت TCP 3478 برای اتصال کلاینت TURN
فعال است؛ `no-tcp-relay` رلهٔ RFC 6062 را خاموش می‌کند، نه اتصال TCP کلاینت.

این نمونه TURN روی UDP/TCP دارد؛ **TLS ندارد**. اگر اینترنت کاربر فقط
TLS روی 443 را عبور می‌دهد، TURN/TLS روی یک سرور/IP مستقل با گواهی معتبر
فراهم کنید و URL آن را به `STREAM_TURN_URLS` اضافه کنید. پورت 443 همین
سرور در اختیار Apache است؛ آن را برای Coturn اشغال نکنید. TURN از پروکسی
HTTP معمولی Apache عبور نمی‌کند.

کانفیگ خصوصی `deploy/turn/private/turnserver.conf` نباید وارد گیت یا image
وب شود؛ هر دو مسیر exclude شده‌اند. برای تغییر image می‌توان `COTURN_IMAGE`
را هنگام اجرای Compose جداگانه تنظیم کرد. image پیش‌فرض نسخهٔ ثابت رسمی است.

## آزمون پذیرش واقعی

1. پس از تنظیم TURN و بازکردن فایروال، موقتاً در `.env` مقدار
   `STREAM_ICE_TRANSPORT_POLICY=relay` بگذارید و سرویس وب را recreate کنید:
   `docker compose up -d --no-deps --force-recreate web`.
2. مدرس و دانشجو در دو مرورگر/حساب و دو شبکهٔ متفاوت وارد کلاس شوند.
   صفحه‌های قدیمی باید refresh شوند. چت، تصویر، صدا و اشتراک صفحه را بررسی کنید.
3. در `chrome://webrtc-internals` اتصال باید `connected/completed`، مسیر منتخب
   باید candidate نوع `relay` و شمارندهٔ `inbound-rtp` و `framesDecoded` رو به
   افزایش باشد. داشتن `ontrack` یا تصویر خود مدرس کافی نیست.
4. حالت فقط صدا، تغییر کیفیت، قطع/وصل شبکه، اجازه/لغو دوربین دانشجو و
   ادامهٔ کلاس پس از تازه‌شدن اعتبارنامه را بررسی کنید.
5. مقدار policy را به `all` برگردانید و وب را recreate کنید. دریافت رسانه
   هم از مسیر مستقیم و هم از TURN مجاز خواهد بود.

تا زمانی که آزمون مرحلهٔ ۳ موفق نشده، انتقال واقعی بین دو شبکه تأیید نشده است.
اگر chat وصل و رسانه قطع باشد، پیام خطا و دکمهٔ تلاش دوباره در نمای موبایل
و دسکتاپ نمایش داده می‌شود؛ لاگ مرورگر جزئیات محرمانهٔ SDP/رمز TURN را چاپ نمی‌کند.

## خطای 403 دریافت image از Docker Hub

Coturn همین نسخه را در رجیستری رسمی GitHub نیز منتشر می‌کند. برای حفظ نسخه،
ابتدا image را از GHCR دریافت کنید:

```bash
docker pull ghcr.io/coturn/coturn:4.18.0-r0
```

اگر کانفیگ با نسخهٔ اولیهٔ راه‌انداز ساخته شده است، یک بار این ترمیم بی‌خطر
را اجرا کنید؛ گزینه‌های حذف‌شدهٔ `no-cli` و `no-dtls` پاک می‌شوند. کلید
موجود، مالک فایل و سایر گزینه‌ها حفظ و بکاپ خصوصی ساخته می‌شود:

```bash
python3 deploy/turn/repair-config.py
COTURN_IMAGE=ghcr.io/coturn/coturn:4.18.0-r0 docker compose -f deploy/turn/compose.yaml up -d
docker compose -f deploy/turn/compose.yaml logs --tail=40 turn
```

متغیر `COTURN_IMAGE` در فرمان بالا فقط برای همان اجرا تنظیم می‌شود؛ در
اجراهای بعدی Compose TURN هم آن را تکرار کنید تا image به Docker Hub برنگردد.
این انتخاب به Compose اصلی آوید یا کلید TURN دست نمی‌زند. اگر GHCR نیز
قابل‌دسترسی نباشد، خروجی همان pull را برای بررسی مسیر شبکه نگه دارید.
